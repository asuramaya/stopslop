This page lists what we plan to build over the next three quarters, when we expect to ship it, and what we've decided not to do.

We keep it public for a selfish reason. When teams tell us early that a feature won't work for their setup, we save a quarter of rework. Half the items below changed shape after someone filed an issue arguing with the design.

A few notes on how to read it. Dates are estimates. Anything under **Now** has an owner and a branch. **Next** means we've written the spec and expect to start within a quarter. **Later** means we agree the problem is real and haven't solved it. Items move backward as often as forward.

Security patches, performance work, and bug fixes ship continuously, and none of that appears here. The roadmap covers changes to the product surface: new commands, new integrations, breaking changes to the CLI and the API. If you only care about what might break your build, read the **Breaking** tag and skip the rest.

Every item links to a GitHub issue. Comment there if we've got the priority wrong, and tell us what you're trying to do rather than which feature you want. We read all of them and reply to most.
