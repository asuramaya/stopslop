Slow queries eat into every feature you ship. This session covers how to find the ones actually costing you time and fix them without guessing.

We open with query plans. You'll learn what a sequential scan tells you, when an index helps and when it doesn't, and how to catch a join that pulls in ten times the rows it needs. From there we move into index design: composite keys, partial indexes, and the tradeoffs each one makes against write speed. This part runs longer, since index design is where most tuning decisions actually happen.

The second half covers connection and query behavior under load: connection pooling, batching writes, and catching N+1 patterns before they hit production.

We close with a live tuning session on a real dataset, checking query time before and after each change so you can see the effect directly.

This is for engineers who write SQL regularly and want to stop treating the database as a black box. Bring a query you've been meaning to fix. We'll work through a few from the audience live.
