Engineering culture at [Company]

We ship in small increments and read the diff before we merge it. Code review is where junior and senior engineers argue as equals; the question is always "does this work and can the next person change it," not who wrote it.

We write tests for the bugs we've actually hit, not for coverage numbers. We delete code as often as we add it. If a service has been quietly rotting, we say so in standup and put it on the roadmap instead of working around it forever.

On-call is shared. Whoever built a system carries the pager for it, and postmortems name the failure without naming a scapegoat. We fix root causes, not the symptom that paged us.

We don't do 2 a.m. deploys and we don't do open-ended overtime. Estimates come from the person doing the work, and if a deadline doesn't fit the estimate, we cut scope, not sleep.

New engineers get a mentor and a first-week project scoped to ship, not a month of onboarding docs. We'd rather answer questions in a pull request than write a wiki page no one reads.

Architecture decisions get written down, with the alternatives we considered and why we didn't pick them. Six months later, when someone asks "why does this work this way," the answer is in the repo, not in someone's memory.

We use the tools that fit the problem. No mandate to chase whatever framework is trending, no attachment to legacy choices past their usefulness. If a tool is slowing the team down, we replace it.
