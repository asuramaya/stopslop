Here's what's next for our developer tools, and how we picked it.

Every item on this roadmap started as a support ticket, a GitHub issue, or a conversation at a conference booth. We track requests on a public board, and the features listed here have the most votes and the clearest path to shipping. If something you asked for isn't listed, check the board before assuming we forgot — it might already be scheduled for a later quarter.

We split the roadmap into three buckets: now, next, and later. "Now" means active development, usually with a preview build you can install today. "Next" means design is done and we're writing code. "Later" means we agree it matters but haven't committed to a date. Dates move. When they do, we'll say why in the changelog rather than quietly deleting the old estimate.

Two commitments guide the choices here. Nothing on this roadmap breaks your existing CI pipeline without a major version bump and a migration guide. And whatever ships for VS Code ships for JetBrains and Neovim in the same release cycle, not months later.
